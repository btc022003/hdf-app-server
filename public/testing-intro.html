自动化测试入门

一个真实项目带你认识"自动测试"到底是什么 · 面向刚入行的测试新人

📋 开场：为什么需要自动化

场景：开发说"医生管理功能做完了"。你去测——打开后台，点新增，填名字，选科室，点保存。再打开列表看看有没有。再编辑、再删。每次发版你都要重复这些操作。

这还只是一个功能、一个角色、一次。实际项目有十几个模块、几百个接口。人手点一遍要多久？

"把人手工点的步骤写成代码，一键运行，自动告诉你过没过。"
这就是自动化测试。不是魔法，就是"做事 + 检查"的翻译。

涉及的工具有：

  • Docker — 把项目跑起来
  • PostgreSQL — 数据存在哪
  • uv — Python 依赖管理，一条命令装完所有插件
  • pytest — 测试的骨架，把所有用例组织起来
  • requests — 调 HTTP 接口
  • Playwright — 操控浏览器
  • Faker — 自动生成假数据
  • Allure — 出报告

🏗️ 先看一眼我们要测的东西

这不是模拟项目，是真的上线跑的医院预约系统。

换个生活化的说法：
你在餐厅点菜。
菜单 = 管理后台页面
服务员 = API（你把需求告诉他）
后厨 = NestJS（实际做菜的人）
冰柜 = 数据库（食材存放的地方）

测试也有两个层次：

  • API 测试 — 绕过"菜单"，直接跟"服务员"对话。快、稳、不需要浏览器
  • UI 测试 — 扮演"顾客"，打开菜单、点菜、看到菜上桌。更像真实用户

📦 每个技术是干什么的

🐳

Docker

用 docker compose up -d 一条命令启动整个项目（应用 + 数据库），不需要手动装 Node.js、配数据库、改配置文件。

为什么重要：测试的前提是"被测系统先跑起来"。Docker 让这一步从半天缩短到 1 分钟，且环境一致。
⚡

uv

Python 的包管理工具（类似前端的 npm）。uv sync 自动装依赖，uv run 一键执行，比传统 pip 快 10 倍。

为什么重要：新手最怕配环境。uv 不需要先装 Python 虚拟环境、不需要手动 pip install，两条命令搞定一切。
🗄️

PostgreSQL

项目所用的关系型数据库。测试不直接操作数据库——通过 API 增删改查，间接验证数据是否正确落库。

为什么重要：理解数据模型才能写出有效断言。不需要写 SQL，但要知道哪些字段是必填、哪些是外键。
🐍

pytest

Python 最主流的测试框架。自动发现 test_*.py 文件并执行。支持 fixture（前置条件）、parametrize（参数化）、xfail（标记已知 bug）。

为什么重要：它是整个测试体系的骨架——定义"用例怎么写、怎么组织、怎么运行"，具体操作交给 requests 和 Playwright。
📡

requests

Python 里发 HTTP 请求的事实标准。测试中对后端接口做增删改查：get()、post()、patch()、delete()。

为什么重要：REST API 测试的核心工具。不需要浏览器，直接调接口拿数据，速度最快、最稳定。
🌐

Playwright

微软出品的浏览器操控工具。能打开 Chromium，模拟用户点击、输入、翻页，验证页面元素是否正常渲染。

为什么重要：requests 只能测接口，测不到"用户打开页面看到什么"。Playwright 让测试站在用户视角验证 UI。
🎲

Faker

一行 fake.name() 生成随机中文名，不用手写"张三""李四"。支持姓名、地址、手机号等数十种类型。

为什么重要：测试数据要唯一、不重复。每次跑都是新数据，避免"用户名已存在"这类冲突。
📊

Allure

把 pytest 运行结果变成 HTML 可视化报告：通过率、耗时、失败截图、步骤拆解，一目了然。

为什么重要：测试跑完不是结束，报告才是交付物。让非技术人员也能看懂测试结果。
📝

Python

写测试用例用的语言——语法接近自然语言，生态最丰富，测试领域的事实标准。

为什么重要：不需要学 Java/C# 那套重型框架。Python + pytest + requests 三件套，新手一两周就能上手写用例。

👀 一条测试用例实际长什么样

拿"创建医生"举例。手动步骤是：登录 → 点新增 → 填表单 → 点保存 → 检查结果。

写成自动化代码：

# 1. 准备数据（Faker 自动编的，不用手写） doctor_data = { "name": "刘医生", "desc": "擅长内科", "departmentId": "科室编号", "doctorTitleId": "职称编号", } # 2. 发请求创建（requests 一行搞定） r = admin_client.post("/admin/doctors", json=doctor_data) # 3. 检查结果 —— 这就是"断言"，自动化测试的灵魂 assert r.status_code == 201 # 创建成功 assert r.json()["success"] == True # 返回标记成功

assert 就是判断题：对 → 绿 ✓，错 → 红 ✗。整个项目 38 条用例，越绿越健康。

📁 测试代码在哪

# 所有测试代码都在这个目录 test/ ├── conftest.py # 全局配置：登录、客户端、浏览器启动 ├── pyproject.toml # 依赖声明（用了哪些插件） ├── uv.lock # 依赖锁文件（确保团队版本一致） ├── test_auth.py # 认证接口：登录成功/失败、权限 401/403 ├── test_doctors_crud.py # 医生增删改查 + 边界异常 └── test_manager_pages.py # 管理后台 16 个页面可访问性 + 权限拦截

🚀 5 步从零跑起来

第 1 步docker compose up -d启动项目（等 30 秒）
第 2 步浏览器打开 /docs确认 Swagger 接口文档能访问
第 3 步cd test && uv sync安装 Python 依赖
第 4 步uv run playwright install chromium安装浏览器（仅首次需要）
第 5 步uv run pytest -v跑！

⚠️ 新人常遇到的两个坑

  • 测试跑得巨慢（2 分钟 6 个用例）：代码里用了 localhost，Windows 先走 IPv6 超时再回退。改成 127.0.0.1 就好了——从 146 秒降到 0.16 秒。
  • 管理员登录失败：seed 初始密码是 admin/admin，不是 admin/123456。看 prisma/seed.ts 确认账号。

💡 记住这几条就够了

  1. "找东西 → 做操作 → 比结果" — 所有测试不管用什么工具，都是这三步。
  2. 先 API 后页面 — 接口测试快且稳，先保证接口对，再测页面 UI。
  3. 数据不手写 — 用 Faker 生成，每次跑都是新数据，互不干扰。
  4. 测边界不测高兴路径 — 成功创建测一条就行，多测"没传参数会怎样""不存在的 ID 会怎样"。
  5. bug 记下来别删 — 用 @pytest.mark.xfail 标记，修好自动提醒。
学自动化测试最好的方法：找现成的 → 跑起来 → 改一行看效果 → 自己新写一个
别一上来就想"我得全学会"——你会被劝退的。
